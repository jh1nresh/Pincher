# Pincher 校園合乘微信小程序試點

這個目錄是給北京大學口腔相關學生做小規模需求驗證的微信小程序前端基線。第一個場景只處理一條清楚的路線：

```text
北大醫學部宿舍 → 北大醫院
```

主流程：

```text
手機號登入 → 固定路線 → 發起／加入拼車 → 行程房間 → 實際車費自行分攤
```

## 這一版要解決什麼

- 讓受邀學生快速看到合適的出發時段。
- 以公共集合點和小型行程房間降低溝通成本，並在房間內協調上車位置。
- 不公開手機號碼，讓乘客只在行程房間內協調。
- 先驗證「有沒有穩定拼車需求」，再決定是否擴充路線、身份驗證和支付。

微信群可以用來邀請和分發，但班次、座位和退出狀態以小程序為準。

## 目前狀態

- 可以直接匯入微信開發者工具預覽。
- 現在使用本地體驗資料；登入頁只是流程展示，不是真實短信驗證。
- `app.js` 的 `demoMode` 在接入正式後端前必須保持開啟；接通後端並完成測試後才可關閉。
- 尚未接入微信支付、錢包或司機接單。
- 固定路線、公共集合點和小型座位數是刻意的試點限制，避免第一版變成網約車平台。

## 匯入和預覽

1. 開啟微信開發者工具，選擇「導入項目」。
2. 項目目錄選擇本 `miniprogram/` 目錄。
3. 可先使用測試號或開發者工具的本地預覽能力。
4. 預覽時可測試：登入、查看推薦班次、發起拼車、加入拼車、進入行程房間、發送集合消息、查看我的行程和退出登入。

正式發布前需要正式小程序主體、AppID、服務端域名和相應服務資格。

## 生產接入順序

1. 後端完成手機 OTP request/verify，回傳短期 access token 與 refresh token。
2. 以 `auth.users.id` 作為唯一 user id；微信 `openid/unionid` 只在服務端綁定。
3. 將建立、加入、取消拼車和房間消息改為服務端 RPC／API，服務端重新檢查邀請資格、座位數、路線、時間和重複加入。
4. 完成北大口腔學生的邀請碼或人工審核流程，避免公開註冊造成陌生人進入。
5. 收緊 Supabase RLS：手機號碼、參與者資料、訊息和舉報不可 public read/write。
6. 補上隱私政策、使用者協議、舉報處理和管理員操作記錄。
7. 法務確認北京私人小客車合乘規則與小程序服務類目，再決定是否接微信支付。

## 收費邊界

試點第一版只計算並展示預估分攤額，實際車費由乘客自行協調，不代收、不托管、不抽成。這不是「微信小程序不能收費」；日後若接微信支付，仍要先確認合資格主體、服務類目、商戶資格和北京相關合規要求。

較適合第一階段的收入方式，是由學校、院系、社團或合作單位支付服務費，而不是向每一趟拼車抽成。

## 安全邊界

不要把以下內容放進小程序目錄或前端程式：

- 短信服務商密鑰。
- Supabase service-role key。
- 微信 AppSecret、商戶私鑰或支付密鑰。
- 管理員 token、cron secret 或任何生產 bearer key。

所有需要權限的操作都應由服務端重新驗證，不能只依賴小程序介面或前端參數。
